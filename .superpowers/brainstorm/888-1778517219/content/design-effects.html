Design — Section 2: Effect System

How effects are defined, registered, and discovered

Effect Trait + Registration Macro
// registry.rs — the core abstraction
trait Effect: Send + Sync {
  /// Unique identifier (e.g. "quantize")
  fn id(&self) -> &str;
  /// Human-readable name
  fn name(&self) -> &str;
  /// Parameter definitions (name, min, max, default, step)
  fn params(&self) -> Vec<ParamDef>;
  /// Allocate any scratch buffers for given dimensions
  fn init(&mut self, width: u32, height: u32);
  /// Apply the effect to a frame
  fn apply(&mut self, frame: &mut RawFrame, params: &ParamValues, ctx: &FrameCtx);
}
// FrameCtx — shared context passed to every effect
struct FrameCtx {
  frame_number: u32,
  width: u32,
  height: u32,
  scratch: &mut RawFrame, // shared scratch buffer
}
// ParamDef — describes a tunable parameter
struct ParamDef {
  id: String,        // "amplitude"
  name: String,      // "Distortion Amplitude"
  min: f32,          // 0.0
  max: f32,          // 0.2
  default: f32,      // 0.02
  step: f32,         // 0.005
}
Writing a New Effect — What You'd Actually Type
// effects/blur.rs — a complete new effect
use crate::registry::{Effect, ParamDef, ParamValues, FrameCtx, RawFrame};

pub struct Blur;

impl Effect for Blur {
  fn id(&self) -> &str { "blur" }
  fn name(&self) -> &str { "Gaussian Blur" }
  fn params(&self) -> Vec<ParamDef> {
    vec![ParamDef::new("radius", "Blur Radius", 0.0, 20.0, 3.0, 0.5)]
  }
  fn init(&mut self, _w: u32, _h: u32) {}
  fn apply(&mut self, frame: &mut RawFrame, params: &ParamValues, _ctx: &FrameCtx) {
    let radius = params.get("radius");
    // ... your blur implementation here
  }
}

register_effect!(Blur);  // ← one line, shows up in studio

Key Design Decisions

Why a trait, not just functions?

Effects like edge detection need scratch buffers (grayscale, edge maps). The trait's init() lets each effect pre-allocate what it needs. A plain function would re-allocate every frame.

Why FrameCtx?

Frame number (for animation), dimensions, and a shared scratch buffer. Passed to every effect so animated effects like distortion can cycle over time without storing global state.

Why f32 for all params?

Simplifies the UI — every param is a slider. Integer params just use step=1.0. Boolean toggles use min=0, max=1, step=1. One UI widget handles everything.

Multiple instances?

The pipeline holds effect instances, not types. You can add "Quantize" twice with different settings — each gets its own params and scratch buffers.
