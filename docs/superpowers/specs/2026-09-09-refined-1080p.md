# Refined native 1080p live painting

User approved 1080p at source ~30 fps, requested more precise styling and efficiency, and raised the target engine budget to about $10/month. Keep psychedelic movement and no persistent trails.

## Artwork

The built-in LivingInk preset now uses native 1920×1080 output, subpixel ridge placement, restrained gradient shoulders, higher line contrast, charcoal 32, no trails, and a smooth 8-second distortion cycle. Distortion interpolates the finished monochrome drawing, preserving defined outlines while avoiding unnecessary RGB-channel work. Source headlight glare still limits car detail. The studio starts from the built-in live preset and uses the same effect, pipeline, and segment renderer.

Preview: `artifacts/living-ink/refined-1080p-30fps.mp4`. Preset: `2026-09-09-precise-ink-preset.json`. Source capture has 180 frames at 30000/1001 fps, 6.006 seconds. No frames are dropped for production.

## Processing

- Incremental decode/render/encode replaces the retained 180-frame RGB batch.
- Squared gradient magnitudes preserve ridge ordering while skipping sqrt/direction work in flat regions.
- Three bounded workers process independent no-trail LivingInk frames. Ordered draining preserves presentation order and frame-based distortion phase. Stateful pipelines remain serial.
- Two encoder threads prevent excessive contention, and RGB conversion storage is reused.
- Caller history is cleared after independent rendering, so reenabling trails cannot resurrect old marks. Rejected/failed source segments clear continuity.
- Defaults: OUTPUT_WIDTH=1920, RENDER_WORKERS=3, ENCODE_THREADS=2. Environment overrides remain bounded. Public endpoints and demand-driven idle shutdown are unchanged.
- The portfolio's initial recorded clip now matches the artwork. It pauses once live video appears or the player is hidden.

## Optional-buffer optimization

Broad-contour and trail buffers now allocate only while their features are enabled and release storage when disabled. The production preset uses neither feature. This removes four full-HD f32 allocations per worker (94.9 MiB logical allocation across three workers), two inactive buffer clears per frame, and the inactive broad contribution read during composition. Actual resident savings are smaller because untouched zero-initialized pages need not be resident.

Compared release builds of baseline `e1728da` and the change on the same 180-frame capture, three workers, two encoder threads:
